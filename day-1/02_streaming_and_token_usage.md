# Streaming & Token Usage

When an application communicates with an LLM, the model may generate a response incrementally rather than waiting for the complete response before displaying anything.

Two important areas in LLM applications are **streaming responses** and **token usage tracking**.

## Streaming Responses

A standard LLM request generally works like this:

```text
Application
     ↓
   LLM
     ↓
Complete Response
     ↓
Application displays response
```

The user may have to wait until the entire response has been generated.

With **streaming**, the response is delivered in smaller chunks as they are generated:

```text
Application
     ↓
   LLM
     ↓
Chunk → Chunk → Chunk → Chunk → ...
     ↓
Displayed progressively
```

This allows an application to start displaying the response while the model is still generating the remaining content.

In LangChain, streaming can be performed using:

```python
llm.stream(messages)
```

The method yields response chunks that can be processed as they arrive.

## Time-To-First-Token (TTFT)

**Time-To-First-Token (TTFT)** is the time between sending a request to the LLM and receiving the first generated output.

```text
Request sent
     │
     │  ← TTFT →
     │
First output
     │
     ├── More output
     ├── More output
     └── Final output
```

TTFT is an important metric for applications where users expect an immediate response.

A lower TTFT means the application can begin displaying content sooner, improving perceived responsiveness.

TTFT is different from total response time. A model may produce its first output quickly but still require additional time to complete the entire response.

## Token Usage

LLMs process text using **tokens**. Token usage can be measured separately for the input and generated output.

The main metrics are:

```text
Prompt Tokens
     +
Completion Tokens
     =
Total Tokens
```

### Prompt Tokens

Tokens contained in the input sent to the model, including the messages and other input content.

### Completion Tokens

Tokens generated by the model as its response.

### Total Tokens

The combined number of input and output tokens:

```text
Total Tokens = Prompt Tokens + Completion Tokens
```

Token usage is important for understanding API consumption and estimating costs.

## API Cost Estimation

LLM APIs generally charge based on token usage, with pricing typically defined separately for input and output tokens.

Conceptually:

```text
Input Tokens  × Input Price
        +
Output Tokens × Output Price
        =
Estimated API Cost
```

For applications with many users, tracking token consumption becomes particularly important.

For example:

```text
One request
      ↓
Token usage
      ↓
Cost

Thousands of requests
      ↓
Aggregate token usage
      ↓
Overall API cost
```

Token accounting can therefore be used for monitoring, budgeting, optimization, and cost control.

## Token Usage in LangChain

LangChain can expose token usage information associated with a model response.

Usage information can include:

```text
Input / Prompt Tokens
Output / Completion Tokens
Total Tokens
```

LangChain also provides usage metadata associated with responses, allowing applications to inspect token consumption programmatically.

## Streaming and Usage Tracking Together

Streaming and token accounting address different concerns:

```text
Streaming
   ↓
How quickly can the user see the response?

Token Usage
   ↓
How much input/output did the request consume?

Cost
   ↓
How much did the request approximately cost?
```

Together, these concepts are important when building production LLM applications that need to be both **responsive to users** and **efficient to operate**.
