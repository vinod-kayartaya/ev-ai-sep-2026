# Chat Model Basics & Hyperparameters

Large Language Models (LLMs) can be accessed programmatically through APIs. Applications can send text to an LLM and receive a generated response.

Modern LLM applications commonly use **chat-based APIs**, where the input is represented as a sequence of messages.

## Chat APIs vs. Raw Completions

A traditional completion interface can be viewed as:

```text
Prompt → LLM → Generated Text
```

A chat-based interface represents the interaction using messages:

```text
Messages → Chat Model → Response
```

This approach provides a structured way to represent instructions, user input, and conversation history.

## System and Human Messages

Chat-based interactions can contain different types of messages.

### System Message

A **system message** provides instructions and context for the model. It can define:

* The role of the assistant
* Expected behavior
* Response style
* Rules or constraints
* Domain-specific context

For example:

```text
You are a professional technical support assistant.
Provide concise and accurate responses.
```

The system message establishes the context in which the model should process the user's request.

### Human Message

A **human message** represents the user's input or request.

For example:

```text
Explain how REST APIs work.
```

A typical interaction therefore has the following structure:

```text
System Message
      +
Human Message
      ↓
   Chat Model
      ↓
Assistant Response
```

Conversation history can contain multiple messages from the human and assistant, allowing the model to process the interaction as a conversation.

## Chat Models

A **chat model** is an LLM interface designed to work with conversational messages.

An application typically provides:

```text
Messages
   ↓
Chat Model
   ↓
AI Response
```

The response generated by the model can then be processed by the application, displayed to the user, or passed to another part of an application workflow.

## Model Parameters

LLMs provide parameters that influence how responses are generated. Two commonly used parameters are **temperature** and **max_tokens**.

### Temperature

`temperature` controls the degree of variation in generated responses.

```text
Lower Temperature
       ↓
More predictable output

Higher Temperature
       ↓
More varied output
```

Lower values are generally useful when consistent and predictable responses are preferred.

Higher values can produce more variation in wording and are often useful for creative generation.

Temperature affects the generation process; it does not change the model's underlying knowledge or intelligence.

## max_tokens

`max_tokens` limits the maximum amount of output that can be generated.

```text
max_tokens = 100
        ↓
Smaller maximum output

max_tokens = 500
        ↓
Larger maximum output
```

A token is a unit of text processed by an LLM. A token does not necessarily correspond to one complete word.

The actual response may contain fewer tokens than the specified maximum.

## Putting the Concepts Together

A basic chat-model interaction can be represented as:

```text
                 System Message
                       +
                 Human Message
                       ↓
                 ┌───────────┐
                 │ Chat Model│
                 └─────┬─────┘
                       ↓
                 AI Response
```

The model's generation behavior can be controlled using parameters such as:

```text
Chat Model
    │
    ├── Model
    ├── Temperature
    └── max_tokens
```

Understanding these concepts provides the foundation for working with LLMs through chat-based APIs and frameworks such as LangChain.
